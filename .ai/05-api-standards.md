# API Standards

## Compatibility

- Existing route paths, aliases (`/api`, `/api/v1`, configured base path),
  methods, request fields, response fields, and status codes are immutable.
- Fixes may add optional fields or headers but must not rename/remove existing
  content.
- Breaking changes require a new approved API version and migration period.
- CI checks the route baseline and OpenAPI document for unreviewed drift.
- `.ai/baselines/openapi.json` is a generated OpenAPI 3.1 compatibility
  catalog. Every detected declaration records its source route file and
  colocated validator sources; CI rejects route or catalog drift.

## Additive headers

- `X-Request-ID`: accepted from a trusted upstream or generated by the API;
  returned on every response.
- `traceparent`: W3C trace propagation.
- Existing `ETag`, `Retry-After`, `Idempotency-Replayed`, rate-limit, and
  payload-crypto headers remain supported.
- `X-CMMS-Processor-Token` is required only by the existing
  `/users/create_external_token/:email` processor bootstrap. It is isolated
  from user bearer tokens and never returned.
- `/metrics` uses a dedicated bearer scrape credential that cannot be reused
  as a CMMS user or processor token.
- Secrets and authentication material are never echoed.

## Requests

- JSON and URL-encoded limits come from validated configuration.
- IDs, pagination, filters, sorts, and search input are validated before
  service execution.
- Mutating requests support `Idempotency-Key` where retry duplication can
  create business impact.
- Tenant context comes from authenticated identity, never an untrusted body
  field alone.

## Responses and errors

Existing responses are preserved. New endpoints use:

```json
{
  "status": true,
  "message": "Operation completed",
  "data": {},
  "errors": [],
  "meta": {
    "requestId": "uuid"
  }
}
```

Errors include a stable safe `code`, existing `status/message/error` fields,
optional validation `errors`, and request ID. Production responses never
include stack traces or database internals.

## Pagination

- Default page size: 25.
- Maximum page size: 100 unless an existing endpoint contract differs.
- Prefer cursor pagination for new high-volume collections.
- Existing offset pagination remains unchanged until a versioned migration.

## Additive asynchronous asset-report PDF lifecycle

- `POST /reports/assets/generate-pdf-async/:id` accepts the same rendering
  payload/chart snapshots as the compatibility PDF route and returns `202`
  with a tenant-owned job identifier. `Idempotency-Key` includes multipart
  file checksums.
- `GET /reports/assets/pdf-jobs/:jobId` returns only safe job status metadata.
- `GET /reports/assets/pdf-jobs/:jobId/download` returns a short-lived signed
  URL only after successful completion.
- `POST /reports/assets/generate-pdf/:id` remains unchanged and synchronous.
